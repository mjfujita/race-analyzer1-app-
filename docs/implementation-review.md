# 市場評価差・購入記録・学習処理の実装確認書

2026-11-15。ブランチ `feat/market-value-workflow`。開発・ローカル検証版。本番未反映。

## 利用者から見た変更

1. レースを選び「能力・適性」でIDMと距離・会場・コース実績を確認する。実オッズと基準オッズは別の観測として記録する。
2. 「市場評価差」で、能力モデル確率・市場支持率・基準人気・損益分岐オッズ・価格下落時の推定回収を並べる。列名から並べ替えできる。基準オッズを公正価格として扱わない。
3. 「最終予想・記録」で予算上限、配分方針、価格下落の感度、各買い目の最低試算的中率を設定する。単勝・複勝・枠連・馬連・馬単・ワイド・3連複・3連単を比較する。応援馬券は単勝＋複勝として扱い、WIN5は対象外。
4. ACE原案を確認した後、必要なら軸馬を指定する。軸指定は候補券の制約として使い、能力確率そのものを書き換えない。
5. 予想を固定保存する。実際に購入した券と金額は別に記録する。購入は利用者が行う。
6. HJCまたは正式な払戻を照合し、精算を明示保存する。訂正は理由付きで追記し、元記録を残す。JSONを書き出してローカル処理へ蓄積する。

値が欠ける券種は比較不能。予算は上限であり、全額投入を強制しない。0円の見送りも保存できる。複勝・ワイドは入力された表示幅の下端を使う感度分析で、最終払戻の保証ではない。

## 確認用画面

開発サーバ起動中は `http://127.0.0.1:4183/market-preview.html`。架空の8頭で能力・市場・予想・購入・払戻の操作を確認できる。

```bash
npm ci
npm run dev -- --host 127.0.0.1 --port 4183 --strictPort
```

`?state=empty` は情報不足、`?state=error` は保存記録破損の確認用。通常アプリ `/` は従来のログインを維持する。確認画面の保存領域は本来のユーザー領域と別で、通常の `npm run build` には確認画面を含めない。

記録はユーザー・レースごとのブラウザ領域にある。現時点で端末間同期はない。端末移行・保管・学習にはJSONを書き出す。履歴はブラウザ内で追記を守る仕組みであり、外部の改ざん検知付き監査システムではない。

## 自動データ処理

作業コピーのルートで実行する。

```bash
bash scripts/research.sh --inbox "$HOME/Downloads"
```

取得済みTYB/HJC ZIPの検証・重複排除・保存、元DBの完全性監査、IDMと条件モデルの学習、時間順の未使用評価、画面用JSON出力までを一括実行する。元DBは読み取り専用。出力は `pipeline/output/` でGit対象外。

- `model.conditions.json` を「市場評価差 → 学習モデルと検証結果 → モデルJSONを読込」で採用する。
- `observations.json` を「最終予想・記録 → 観測データJSONを取り込む」でTYB/HJC参照に使う。
- 書き出したオッズと購入記録は `--snapshots '/path/odds.json' --ledger '/path/record.json'` で次回処理へ加える。

詳しい形式・実行例は [データ処理の説明](../pipeline/README.md)。ログイン済みブラウザの継続巡回、ZIP自動ダウンロード、画面への自動同期は未実装。今回の「自動化」は手元にある入力の一括処理と、アプリ内の確率・価格・配分・記録計算である。

## 数学上の扱い

- 市場支持率 `q = (1/O) / Σ(1/O)` とモデル確率 `pF` を区別する。
- 評価差 `log(pF/q)` は、基準人気があれば能力と基準人気の差・基準人気と現在人気の差へ分解する。
- 推定回収倍率は `p × O`。表示オッズから控除率をもう一度引かない。
- 馬券間の相関を含む上位3頭の着順分布を列挙する。配分は候補上位32点を100円ずつ比較する探索で、全候補の大域最適を保証するものではない。
- 価格下落率は利用者設定の感度分析。学習済みの最終オッズ予測や統計的な信頼下限とは表示しない。
- 公開時刻・観測時刻・取得時刻、モデルの学習終了・作成・採用時刻を確認する。締切後の情報を使う場合は過去検証として記録する。

## 実データによる検証結果

提供ZIPを解析し552行保存、再実行で追加0行を確認した。元DBの5,046レース中、全頭が完全な3,059レースを処理対象にした。1,549レースは不完全、438レースは取消・同着・完走不整合等として除外した。除外は学習対象の偏りを生むため、全レースへの精度保証ではない。

学習・校正・未使用評価を日付順に分離した。条件モデルの採否は校正期間で決め、未使用評価で選び直していない。直近5走の条件特徴は既存画面側SQLと30レース405頭で一致した。

未使用179レースのlog loss（小さいほどよい）：

| 比較対象 | log loss |
|---|---:|
| 学習したIDM温度モデル | 2.244300 |
| 距離・会場・コースを加えたモデル | 2.195103 |
| 確定オッズの市場モデル | 1.883844 |

条件モデルはIDM単独から改善したが、市場単独より良い予測や正の収益性は確認できていない。確定オッズの比較結果は10分前の市場モデルとして流用しない。全モデルを研究用として表示する。
