# データ処理の実装

`pipeline/` は元JRDB SQLiteを読み取り専用で開き、観測・モデル・検証結果を別のSQLiteとJSONへ保存する。`collector/` は専用のJRDBブラウザ、ZIP確認、定刻/依頼取得、クラウド同期を担当する。

PACIを取り込むときも元DBのコピー上で処理する。既存DBの未コミット変更を上書きしない。TYB/HJCは公式のバイト定義で解析し、出典hashと実取得時刻を追記する。同一入力を再実行しても重複しない。不正なバッチは書き込まない。

`model.runtime-base.json` は初回採用した能力基準。毎回の再学習候補 `model.conditions.json` とは分ける。`model.runtime.json` は当日条件・T10市場校正・最終単勝価格のモデルと、それぞれの学習状態を持つ。初回能力基準より後の時刻付き観測と結果を蓄積して更新し、未使用評価をモデル選択に流用しない。

画面の固定予想・実購入・精算もクラウドから取り込み、訂正履歴を保って集計する。予想を購入扱いせず、HJCにない取消・返還を推測して精算しない。

時刻がない過去ZIPや締切後に閲覧したオッズ履歴は、実際に締切前に取得した証拠にしない。画面で直接観測した証拠は、その実取得時刻だけを証明する。詳細は [モデル](runtime-models.md)、[API](../server/README.md)、[ローカル処理](../pipeline/README.md)、[取得ワーカー](../collector/README.md) を参照。

本番反映と実疎通の確認は `production-release.md` に記録する。処理が実装済みでも、データ不足のモデルは推定保留となる。
