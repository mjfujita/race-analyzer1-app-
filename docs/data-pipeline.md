# データ処理の実装と検証

`pipeline/` にPython標準ライブラリで動くローカル処理を追加した。実行方法とデータ形式は [pipeline/README.md](../pipeline/README.md) を参照。

## 完了した処理

- 元のJRDB SQLiteを `mode=ro` と `query_only` で開き、別DBへ取込み履歴を追記する。
- 全頭完全性、馬ID、レース日、頭数、着順、IDM・確定オッズの欠損を監査する。
- 公式のバイト定義に沿ってTYB/HJCを読み、版・元内容ハッシュ・取得時刻を保存する。
- 時刻付き単勝オッズsnapshotを検証・追記する。正式な全頭が確認できない入力は拒否する。
- 画面の予想・実購入・払戻記録を取り込み、訂正履歴を保って出力・集計する。
- HJCの払戻を購入記録へ照合する。HJCにない返還情報は確定扱いにしない。
- 時間順の学習・校正・未使用評価を実行し、研究用のIDM温度モデルを出力する。
- 直近5走の距離・会場・コース特徴を各予想日より前の結果だけで再計算し、正則化付きの追加モデルを校正期間で比較する。未使用評価は選択に使わない。

## 検証

合成データの自動テストで、8券種・9桁払戻、日本語を含むTYBのバイト位置、全頭欠損、時刻不整合、NaN、ZIP再取込、バッチ途中の不正入力、返還収支、記録訂正、元DBの書込み拒否、時系列分割、ワンコマンド出力を確認する。

利用者提供のTYB/HJC ZIPもローカル出力へ解析・取込みし、元DBの監査・学習処理まで実行した。元DBと本番環境は変更していない。実データの生成物は `pipeline/output/` 以下のGit除外対象。

## 残る制約

入力時刻のない古いデータは、実際の10分前予想を再現する証拠にはならない。確定オッズで選んだ市場モデルと仮の回収診断は研究専用。展開・当日傾向・天候・パドック係数、最終オッズの学習、統計的な収益性下限は未実装である。

この処理は、手元へ取得済みのファイル・ブラウザからの記録書き出しを自動処理する。ログイン画面の継続巡回や新しいZIPの自動ダウンロードは実装していない。元のZIP・確定結果・時刻付き観測が揃ってから、それぞれのモデルを拡張する。
