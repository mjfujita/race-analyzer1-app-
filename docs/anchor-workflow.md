# 軸候補と妙味判断

レースを開くと「軸候補・妙味判断」を表示する。AIは条件を満たす候補を最大2頭提示し、利用者が1頭を軸に選ぶ。流し・ボックス等の券種、相手、購入額は利用者が決める。候補を2頭揃えるための補充はしない。

## 候補の条件

- 推定3着内率が設定値以上で、下落想定後の単勝または複勝の期待回収率が100%を超える馬を選ぶ。並び順は3着内率、勝率、馬番の順。
- 初期値は3着内率50%以上、価格下落10%。いずれも画面で変更でき、保存時の条件を固定する。この初期値を過去結果で最適化した扱いにはしない。
- 単勝の期待回収率は推定勝率×取得倍率。複勝は発売時の的中範囲に対応する確率×取得倍率下限。価格の下落は倍率に適用し、確率を変えない。
- 発売時5〜7頭の複勝は2着以内、8頭以上は3着以内。取消後も発売時頭数を保持する。3着内率はこれと別に表示する。
- 複勝オッズは同じレース・同じ単勝観測時刻の直前情報から取得する。ない馬は取得済み単勝だけで判定し、複勝を推測で埋めない。
- 全頭の勝率・単勝価格等が不足または不正なら「判断保留」。取得できた価格で条件を満たす馬がなければ「見送り」。候補があっても手動で見送れる。

3着内率は既存の全頭勝率から着順を列挙するモデルによる未校正の参考値。3着内率の実績校正や正の収益性は未確認。既存の勝率校正・採否停止は従来どおり勝率に適用する。単勝／複勝の期待回収率は各券種の価格を比較する指標であり、利用者が組み立てる馬連・ワイド・3連系の回収率を表さない。

## 人気の推移

同日同レース・同じ全出走馬について、選択した時点までに取得済みの観測履歴だけを使う。最初の適格観測と現在選択中の観測を比較し、倍率の変化率、人気順位、逆数を全頭で正規化した市場支持率の相対変化を表示する。倍率低下と市場支持率上昇の両方がある馬を「人気上昇傾向」と表示する。実際の投票額増加や勝率向上とは断定しない。

基準オッズ、別レース、時刻不明の旧記録、選択時点より後に取得した訂正版は比較に含めない。適格な2時点がないときは比較待ち。最新価格で妙味が消えた馬を、人気上昇だけで軸候補に戻さない。過去の観測を選んだ場合、当日情報・学習版も選択した取得時点までに制限する。

## 保存と互換性

`anchorSelection.method=place-value-single-v2` で、AI候補0〜2頭、選択した1頭またはnull、判断（候補提示・選択済み・見送り）、3着内率の条件を保存する。全頭勝率、単勝・複勝価格、価格取得時刻、比較元の観測も固定し、保存表示は現在の条件変更から独立して再現する。

AI原案と利用者判断は別レコードとし、予算0・配分なしで保存する。購入・精算とは別。既存の本人専用クラウドAPIと締切前受領を利用し、JavaScript・Python両側で候補と判断を再計算して検証する。旧 `win-value-two-v1` の記録は旧2頭方式として読み込める。

DB migration・権限変更は不要。新形式の記録をPythonワーカーが読めるよう、リリース時はアプリ／APIに加えてワーカーのコードも更新する。切り戻しでは予想JSONを保持し、新形式記録の非対応版への読込みを避ける。
