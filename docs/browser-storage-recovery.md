# ブラウザー保存容量不足への対応（2026-11-28）

## 確認した原因

利用者の京都7R画面に、`race-companion-cache:v1:...`と`race-prediction-journal:v1:...`の両方で`exceeded the quota`が表示された。ブラウザーの同じサイト内の保存領域が満杯になり、一時コピーと予想・結果記録の書き込みが失敗したことを示す。PC全体のディスク容量やJRDBの配信停止を示すものではない。

先のPR #34は同期中・同期失敗後のボタン制御の修正。画像で特定できた容量不足そのものには追加対応が必要なため、同じグループ登録障害の修正として続ける。直前の「本番にお願いします」による反映依頼を継続し、検証後に反映する。

## 保存方針

- 整理対象は、同じ利用者の`race-companion-cache:v1:{userId}:...`だけ。クラウドから取得済みのレース一時コピーで、再取得できる。
- 古い`fetchedAt`から整理し、コピー全体に512Ki文字の予算を設ける。実ブラウザーのquotaを固定値と仮定せず、quota例外時にも必要なコピーだけを取り除いて再試行する。
- 現在書き換える保存先自体は整理対象から外す。書き込みに失敗しても、その保存先の旧値は保持する。
- 予想・結果・グループ登録・購入・精算・未同期記録・オッズ履歴・取得観測・設定・モデル・端末認証は削除しない。別利用者の一時コピーも対象外。
- 同時保存ロック、追記履歴、入力検証、サーバーの競合チェックは既存のまま。記録の形式・時刻・API・DB schema・認証方式・確率計算・取得ワーカーは変更しない。
- 一時コピーを全て整理しても空きが足りない場合、記録を削除せず「ブラウザーの保存容量が不足」「今回の端末への保存は未完了」と日本語で表示する。保存成功を偽らない。
- 一時コピーを整理した古いレースを再び開く際は、クラウドとの同期が必要。オフラインでは取得済みの全レース詳細が常に残る保証はない。

## 検証

Nodeテスト：同じ利用者のコピーだけ整理、各記録・認証の保持、古い順の整理、コピー予算、整理不能時の旧値保持、日本語エラー、quota以外のエラー、別アカウントの保護、オッズ保存先の所有者解析を確認。

Chrome E2E：実際のlocalStorageをquota例外まで満杯にした。再読み込みで同期が復旧し、未送信予想・既存登録・オッズ等の保存値が完全一致で残り、グループ更新が認証API・immutable storeに2件目として保存されることを確認。画面実行エラー0、390px表示も確認。

## 反映と復旧

本番切り替え前に検証済みコミットとmainのツリー一致、候補配信のJS/CSS一致、匿名APIの401を確認する。本番保存記録への書き込みはしない。反映結果・検証数・デプロイID・復旧元は当該PRのリリース記録に残す。

戻す際は直前のデプロイへpromoteする。整理済み一時コピーはクラウドから同期し直す。予想・グループ・結果等を巻き戻さない。サイトデータの全消去や再認証は復旧手順に含めない。
