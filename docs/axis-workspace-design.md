# 軸選択ワークスペース

目的：最大2頭の候補から1頭の軸を決め、買い方は利用者が選ぶ流れへ画面を整理する。
完成条件：主メニュー4項目、レース内4項目、取得/学習/設定の分離、PC比較表とモバイルカード、過去記録と復旧経路の保持。
工程：既存調査 → UI実装 → 単体/統合/ブラウザ検証 → レビュー可能なコミット・PR。今回の到達点は本番反映前。
自律範囲：画面・表示設定・テスト・ドキュメント。DB・認証・クラウド設定は維持。既存APIの所有者向けGETに受領証跡を追加し、選択した軸・見送りの締切前受領も証明する。
分岐：欠損は未取得/未算出、通信失敗はエラー、締切後は参考試算。モデル性能や時刻のサンプル値は製品へ入れない。
Pre-decision：既存台帳と予測計算を再利用。保存履歴は削除しない。旧分析と自動配分を主導線から外す。
Human Gate：本番反映・mainマージは今回行わない。既存の取得ワーカー・未承認のデータ送信は再開しない。
停止条件：不可逆な変更、認証境界の変更、実データ欠損を伴う場合。
影響：追加の表示設定はユーザー別のブラウザ保存。既存の予想・購入・精算・PACI・観測形式は変更しない。受領判定は同じ元オッズ・サーバー時刻・締切検証を利用し、校正学習は引き続きACE原案だけを対象とする。
ロールバック：このUIコミットをrevertする。追加設定キーは旧版から無視され、台帳は継続利用できる。

## 表示・運用の決定

- 主メニューは「本日のレース」「予想・軸選択」「振り返り」「データ管理」。レース内は軸候補・能力適性・オッズ推移・展開馬場。
- 旧分析・シナリオ・自動配分は通常の導線から外す。PACI一覧・DB再取得・TYB/HJC補完・JSON台帳の取込/書出し・購入/精算/訂正は保持。
- 表示設定は本人別のブラウザ保存。未保存レースの初期値に適用し、固定済み予想は再計算で上書きしない。
- 振り返りの軸判断は本人ブラウザ内の記録を対象にし、直近48保存レースを最大4並列の読取専用GETで受領照合する。集計は締切前受領を確認できた各レースの最終判断と、同じ全出走馬の正式結果だけ。後の参考試算は先の正式判断を隠さない。
- 購入未記録・未精算の予想から実回収率を作らない。受領未確認・異常着順・データ未取得は明示する。クラウド受信の観測単位の時刻は現APIでは未確認のため、観測・Mac取得・ブラウザ受信と区別する。
- API変更は既存GETのreceipts追加と、検証済み1頭選択/見送りのuser記録への受領発行。所有者、元オッズ、サーバー時刻、締切、モデル証跡の既存検証を通す。DB migration・権限・環境変数変更なし。
- 勝率校正の学習は引き続きACE原案を対象とし、user受領追加で学習件数を増やさない。ワーカー向けpull-ledgersの受領一覧はACE原案だけに維持し、旧ワーカーがuser受領を読み込んで失敗する変更を避ける。将来生成/採用された能力モデルは軸画面・通常オッズ画面・展開画面へ遡及させない。展開画面は現在時刻と発走10分前の早い方を上限にし、脚質の分類を主表示、参考シナリオと補正の詳細を折りたたむ。

## 確認

ローカルの架空データでブラウザ→既存APIハンドラ→メモリストア→台帳→表示を検証。本番・実データ・取得ワーカーの稼働状態は変更しない。
全変更はPR #8の軸予想ブランチを土台とする。本番に進む場合は先に依存関係を解決し、アプリ/APIと互換性のあるPythonワーカーを同版へ揃える。
