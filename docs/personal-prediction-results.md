# 私の予想と当日の結果一覧

## 利用する流れ

1. 「グループ・買い目」で、自動分類の区切り・候補除外を自分で調整する。
2. 各群と各馬の着順確率を見て、馬単・3連単・3連複の組み立てを選ぶ。群から1〜3着（3連複は1〜3頭目）に追加できる。
3. 「私の予想」で、フォーメーション・BOX・群軸ながしを選び、馬番と重複除去後の全買い目を確認して保存する。配分・予定予算・購入額・回収率は入力しない。100点などの金額由来の上限はない。
4. 「画像・手入力で結果を登録する」で、当該レースの上位3頭と券種別の確定払戻（100円あたり）を登録する。払戻は空欄でもよい。後から結果・払戻を訂正でき、訂正前の内容も保持する。
5. 当日の一覧で、予想した群／その候補頭数／買い目点数／全体の対象頭数／実際の群と馬番／買い目への包含／確定払戻を確認する。PCは表、スマホは全項目が読めるカード状の一覧。会場を絞り込める。

チャットに送付された画像は、このAPIへ人間または認可済みアシスタントが転記する運用。Webアプリがチャット添付を自動取得・OCRする機能ではない。購入予定の画像だけでは実購入済みにしない。JRA-VANで把握する実収支を重複管理しない。

## 保存と照合

- 新規予想は `predictionJournal.js` のselection形式。保存時の観測・手動分類・候補除外・着順の群・群と各馬の確率・馬番・全買い目を固定する。観測の同期やその後の群の編集で書き換えない。
- グループ全体の確率と頭数補正、各馬の着順確率には既存ACEと同じ経路を使用。未校正の試算。過去の予想を結果で再計算しない。
- 結果は全頭分の着順を要求せず、上位3頭だけで比較する。馬単は上位2頭、3連複は着順不問。下位着順を捏造しない。
- 同着・異常結果は保留として記録し、通常照合から除外する。今回の簡易入力は同着の全組み合わせ精算を扱わない。
- JRDBの正常な確定画面結果が取得できれば自動で照合できる。画像・手入力の出典と日時はそのまま保持。手入力とJRDBの着順または払戻が競合すれば照合を保留する。
- 払戻欄は勝った組み合わせの100円あたりの金額であり、その予想に的中がなくても表示する。実受取額・損益・回収率には換算しない。
- 発走前クラウド受付の有無を表示。後からの保存や未同期の予想を発走前の検証実績に見せない。
- 群別着順回数は、会場フィルタ内で結果照合できた各レースを1度だけ数える。予想とは別に最後に明示登録した分類を使い、未登録は数えない。独立登録は [group-registration.md](group-registration.md) を参照。事後・受付未確認も含む記述集計で、能力帯や頭数が揃った統計検証・次レースの確率ではない。

## API・データ・権限

- 既存のowner本人／承認端末の認証を使う。collectorトークンから予想・手入力結果を保存する権限は追加しない。
- `GET /api/companion?journal=1&raceDate=YYYYMMDD` : 本人の当日予想・訂正履歴・サーバー受付時刻・既存のgroupPlansを取得。
- `POST /api/companion {action:"save-journal", record}` : selectionまたはresultを追記。同じIDの同じ内容は冪等、異なる内容は409。
- 予想は同期済みのsnapshot ID・オッズ・観測/取得日時・発走時刻・全出走馬と照合する。未知の馬番や他レース・未来の登録日時を拒否。
- result: raceId、raceDate、numbers（1〜3着順）、payouts（type/per100）、source（manual/user-image）、evidence（画像名など）、replacesId（訂正元）。createdAtは実登録日時。過去に遡らせた受付やJRDB観測にしない。
- private既存bucketに `{owner}/v1/prediction-journal/{date}/predictions|results|result-links/...` を追加。本文とサーバー受付時刻をcreate-onlyで保存。訂正元の予約で同時訂正の二重分岐を防ぐ。
- 結果訂正はクラウド成功後にローカルへ反映する。失敗時はフォームを維持し、同内容の再送で同じIDを再利用する。予想はローカル保存後に同期し、失敗時は「未同期の記録を再送」から再送できる。
- 旧groupPlans・purchases・settlements、既存PACI/JRDB観測、学習入力は変更しない。旧配分・購入記録UIは折り畳んで閲覧可能。旧予想は当日一覧に読み取り専用で表示する。
- DB schema / migration / 認証・RLS設定の変更なし。APIとprivate objectの追記形式を追加する。
