# 全レースの結果とグループ傾向

## 目的と画面

「予想・結果」を開くと、最初に当日のグループ傾向を表示する。個別に予想を登録する操作は不要。

- 本人限定の当日開催カタログ全件を母集団にし、予想やグループ登録のないレースも表示する。
- 会場を選んで、A・B・C等の1着／2着／3着回数を一覧の先頭で確認する。
- 各レースを1着／2着／3着の3列で並べ、群・馬番・馬名・群の頭数を表示。登録時の確率がある場合は併記。
- 結果待ち・分類待ち・照合保留も行を消さず、集計可能件数と区別する。出現0回の群も列の合計に含める。
- 「選択レースの予想・照合」への切替と各レース行の詳細導線を残す。個別比較と全体傾向を分け、保存予想だけの一覧を初期表示しない。

## 分類の優先順位

1. ユーザーが独立登録した分類があるレースは、その最終登録を優先する。設定を自動修正しない。
2. 未登録のレースは同じレース・日付の全頭オッズを使い、倍率差1.5倍による既存自動分類を読み取り専用で計算する。予想やグループ登録を自動作成しない。
3. 自動分類は、締切前に実際に取得した新しい観測を優先。なければ発走前の観測を参考として使う。発走後の観測・確定オッズしか利用できない場合は「自動・確定後参考」と明記する。取得時刻を遡らせない。
4. 全頭のオッズが欠ける場合は、結果の馬番を表示したまま「分類待ち」。未知の馬・別レース・未来の観測で補完しない。

集計は各レースを一度だけ数える。全頭が同じ群でも、1着／2着／3着をそれぞれ一回数える。ユーザー登録／自動／参考の内訳を表示する。結果が競合・保留なら通常回数に入れない。これは当日結果の記述集計で、次レースの予測確率・回収率ではない。

個別の保存予想は引き続き保存時の分類と馬番を固定し、的中照合も保存した買い目で行う。全体傾向での自動分類を、保存済みの予想・ユーザー登録・購入へ転記しない。

## 技術と反映

- `automaticResultGroups.js`: 全頭観測・時点の確認と分類。現行のgroupOddsと同じ方法を使用。
- 本人限定journal GETへ `automaticGroups` を追加。従来から結果抽出に読み込む観測を利用するため、レースごとの追加ネットワーク取得なし。古いクライアントは追加フィールドを無視できる。
- `RaceGroupTrends.jsx`: 全レース一覧・会場別集計。`RaceResultsWorkspace` の初期表示を傾向へ変更。
- DB schema・migration・権限・認証・学習・確率モデル・取得ワーカーの変更なし。実レコードを書き換えない。
- 本番取込済みの24レース・結果8レースを読み取り専用で照合し、8レースすべてがグループ集計に含まれることを確認。登録1・自動7（うち発走前参考1）。この時点の件数は増える可能性がある。
- 検証済みコミットをPRからmainへマージし、本番候補のアセット一致・認証確認後にpromote。切り戻しは直前deploymentへ戻すだけで、保存データの変更は不要。
