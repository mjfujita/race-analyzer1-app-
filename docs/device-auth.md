# 本人のPC・スマートフォンの端末認証

## 利用手順

1. 既存の本人ログイン済みPCで右上「端末認証」を開き、「この端末を承認する」を押す。
2. 「スマホ登録用QRコードを発行」を押す。本人のスマートフォンのカメラで読み取り、開いたブラウザで「この端末を登録」を押す。
3. 以後、同じブラウザで通常の本番URLを開く。登録は180日間有効。Cookieの削除・別ブラウザ・期限切れでは再登録する。
4. 紛失時は残った端末の「端末認証」で該当端末を解除する。解除操作は確認後に実行される。予想・購入記録は削除しない。
5. 全端末を失った場合は未承認画面の「本人確認による復旧」から既存の本人アカウントでログインし、新しい端末を承認する。

通信障害・認証APIの一時エラー・不正な応答・15秒の確認タイムアウトは「未承認」と区別する。「端末の承認を確認できません」と再確認ボタンを表示し、承認Cookieを削除したり再登録を求めたりしない。確認できるまでアプリの表示・操作をブロックするが、開いていた画面の状態は保持する。通信復帰・画面復帰・60秒ごとの確認、またはボタンで再試行する。正常応答で未承認・解除・期限切れが確認された場合は従来どおり拒否する。

「端末」はブラウザの保存領域単位であり、ハードウェア証明や生体認証ではない。スマホの登録完了は当該スマホでの登録操作と一覧への反映で確認し、QRを表示しただけでは登録済みと扱わない。

## 実装と保護

- `/api/device` が本人の既存Supabaseアカウントで初回登録を認可する。アカウントのowner IDは固定し、旧記録の所有者・保存キーを維持する。
- 通常利用は暗号学的乱数256 bitの不透明な `__Host-race_device` Cookie。Secure / HttpOnly / SameSite=Strict / Path=/、180日。サーバー側はSHA-256のみを索引として保存し、生トークンは保存しない。
- 私有 `race-research` バケットの `owner/v1/devices/` 配下へ登録・失効記録を追記。既存RLS・バケット公開設定・DB schema・環境変数の変更なし。
- スマホ追加のコードも256 bit、10分・一回限り。秘密はURL fragmentへ入れ、ページ読取後に消去。URL query・外部QRサービス・永続ブラウザストレージには保存しない。QRはブラウザ内で描画する。コードを知る者は登録可能なので本人以外へ渡さない。
- 引換済み記録をcreate-onlyで先に保存するため、同時引換の成功は一件のみ。引換後の通信・保存エラーではコードを再利用せず、PCで新しく発行する。
- 期限切れ・解除済み発行元・不正コード・認証障害では拒否する。端末登録履歴64件で停止、通常の承認中端末は8件までを目安とする。複数の異なるコードを同時引換した場合の厳密な台数予約はしない。
- Cookieによる書込はOriginの完全一致と専用ヘッダー、JSONのみを受け付ける。取得・書込ともownerに限定。私有API応答はno-store。
- `/api/device?resource=race-db` は本人だけに固定されたPACIオブジェクトの60秒署名URLを発行する。任意のバケットや保存先は指定できない。
- collector専用POSTトークン、既存アカウント復旧、PACI取込、予想・購入台帳、バックテストとモデル採用条件を維持する。
- 解除後は以後のAPIアクセスを停止する。既に当該端末へダウンロードされたデータを遠隔消去する機能ではない。画面の認証確認は表示中60秒ごと、各APIは毎回確認する。

## 検証と反映

- Node: owner限定、Cookie属性、ハッシュのみ保存、二重引換、期限切れ、解除、CSRF、DB取得制約、異常入力。
- Chrome E2E: 分離したPC/スマホcontextで初回登録、JWTなし再表示、QR引換、モバイル表示、解除後拒否。
- 通常のlint / typecheck / build / 全Node・Pythonテスト / 既存Chrome E2Eも実施する。
- 本番ではログイン済みPCの登録と再表示を確認し、スマホは本人操作後に一覧を確認する。架空の登録や台帳は本番へ作成しない。
- ロールバックは直前のVercel deploymentへpromote。端末登録記録を削除せず保持する。旧版はCookieを認識しないため本人アカウントのログインが必要になる。
