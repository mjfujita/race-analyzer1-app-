# 予想の振り返りと勝率校正

## 利用手順

1. JRDB会員ページに専用ブラウザでログインし、取得ワーカーで発走予定・全頭・単勝オッズを同期する。
2. 発走10分前までに「最終予想・買い目」の「10分前の予想を固定保存」を押す。「締切前の受領を確認しました」と表示されると、予想が学習候補になる。受領には、同じ出走馬・オッズの取得記録がクラウドへ先に同期されている必要がある。
3. 結果の取込後に「予想の振り返り」を開く。保存した全頭の勝率、実着順、予想1位と勝馬、照合と採用の状態を確認できる。複数回固定した場合、学習には最初に受領したACE原案を1レースにつき1件使う。
4. ワーカーが時刻付き結果と予想を取り込んだときに再学習・評価する。ローカルで取込と集計だけをやり直す場合は以下を実行する。

```sh
python3 -m pipeline.run review --output /path/to/research --inbox /path/to/jrdb-zips --include-paci
```

従来の `collector.prepare` がPACIを派生DBに取り込む。振り返りの出力は `forecast-review.json`。ローカルの `market.sqlite` では既存の追記型観測に源泉を保管し、校正版と採用状態を `calibration_versions` と `calibration_state` に分けて保存する。従来の能力・適性モデルや市場モデルは引き続き従来の学習処理で生成する。

## JRDBファイルの用途

| データ | 取込と用途 |
|---|---|
| PACI・BAC・KAB | 現行PACI取込を継続。PACI同梱と単独版の番組・開催を日付とレース／開催キーで振り返りに結び、発走予定・頭数・馬場予想の参照に使う。 |
| BAB・KAA | 旧版の固定長仕様に対応。番組・開催の参考記録として保存する。 |
| KTA | 登録頭数をレースキーで照合。確定出走馬や馬番の判断には使わない。 |
| TYB | 取得した最終版を記録。予測時点の観測には、別途ワーカーが締切前に観測した全頭オッズを使う。 |
| HJC | 単勝の勝馬と払戻を照合に利用。従来の購入精算の扱いを継続する。 |
| SEC・SED | レースキー・馬番・日付、着順、異常区分を固定長のバイト位置で解析する。速報と確定が同名になる場合がある。学習には全頭の着順と単勝払戻の勝馬が一致するレースを使う。 |
| JRDBレース画面 | 全頭着順、単勝最終オッズ表示、単勝払戻を取得できた場合も結果照合に使える。二列の払戻表に対応する。 |
| UKC・CSA/CZA・KSA/KZA・MSA/MZA | 既存のUKC取込を継続。追加ファイルは受領日・ファイルハッシュ・件数を監査用に記録する。週末成績更新などの時点を証明できるまで学習特徴から除外する。 |

結果は同日・同レースキー・馬番集合で照合する。取消・同着・異常着順、着順と払戻の相違、結果待ちを画面に残す。後日入手したファイルの公開日時は不明のまま保存する。収録日の近い会員ページ上のZIPリンクを辿る。契約コースで未提供のデータは、利用権限のあるファイルをダウンロードして `--inbox` または `--zip` で取り込める。LZHは既存の展開手順でZIPを用意する必要がある。

## 学習・採否・停止

- サーバーが発走10分前までの受領を記録し、締切・取得時刻・同期済み全頭オッズを照合する。後からの再試算や受領証跡がない旧予想も画面で振り返れる。学習対象は時刻を確認できた新しい固定予想のみ。
- 予想作成時の校正前勝率を固定し、温度パラメータを当てはめる。能力モデル版と有効な条件・市場の係数が同じ予想を使う。結果閲覧後の再計算で過去の予想を作り直さない。
- バックテストは開催日を単位に、各評価日の締切より前に受領した結果だけで学習窓を広げる。初回採否では最低40レース・10開催日を学習、後続の最低20レース・5開催日を独立評価に用いる。タイムスタンプ付き結果を遡って古い学習窓に入れない。
- 独立評価で校正前と従来採用版の両方に対してLog lossを0.001以上改善し、Brierを悪化させなかった版を採用する。評価済みの日付は次の候補の採否に使い回さない。確率帯別に平均予測と実勝率を表示する。
- 採用後に新たな最低12レース・3開催日で悪化を検知した場合、または採用・監視の根拠となった結果が訂正・失格等で変わった場合、その校正版を外す。業務画面では採用済みで当該モデル構成に合う版のみ使う。採用情報を14日間取得できない場合も校正を外す。

この採否と停止は単勝の勝率校正に適用する。温度校正は馬の順位を入れ替えず、各馬に割り当てる確率を調整する。実用上の性能は本番で締切前記録が蓄積してから評価する。

## リリース手順

1. PRと各テスト結果を確認し、承認済みのデプロイ手順でアプリとAPIを先に更新する。
2. Macのワーカーを同じ版に差し替え、専用ブラウザの認証状態を確認する。従来どおり個人専用のprivate bucketで同期する。Supabaseのスキーマ変更やRLS更新は不要。
3. 次開催でPACI→発走予定・オッズ→締切前受領→結果照合→振り返りの順に確認する。新しい予想は必要件数に届くまで未採用の表示になる。
4. ロールバックは旧アプリ版への切り戻しと以前のLaunchAgentランタイムの復元で行う。保存した予想、結果、モデル版は後続の調査用に保持する。
