# パドック・返し馬コメントの取得と表示

## 利用者の操作

レース詳細上部の「JRDBへ最新取得を依頼」で、Macの取得ワーカーが直前情報に続いて「パドック返し馬」タブを確認する。取得・クラウド送信・画面同期は従来の経路を使う。

「能力・適性」の各馬詳細で、馬体重、JRDBパドック点、原文コメント、コメント欄の確認日時を表示する。コメント本文が提供されない画面では、未取得と混同せず「このJRDB画面ではコメント提供なし（オプション情報）」と表示する。これは契約状況を断定する表示ではない。

初期表示は発走10分前（T10）と選択観測時刻までの情報に限定する。締切後に取得済みの点数・コメントには理由と取得日時を表示し、「最新の参考情報を表示」で内容を確認できる。参考表示に切り替えてもACEの事前予想・確率・保存済み予想は変更しない。

## 取得の検証

- 画面の馬番・全頭の馬名を開催日・レースに対応づけてから、名前付きコメント列だけを読む。
- パドックと返し馬の原文を分けて保存する。不一致・欠損時は部分的な成功として扱わない。
- `paddockCapture` に `status`、実際の `checkedAt`、確認頭数を保存する。状態は `available` / `empty` / `not-provided` / `failed` / `tab-missing` / `not-collected`。
- 観測全体の取得日時は全タブの読み取り完了時点。後から読めたコメントを先の時刻へ遡及しない。
- 点数0と空欄、馬ごとの空欄、取得失敗、旧取得方式を区別する。
- 会員契約・権限は変更せず、表示される内容だけを取得する。原文・点数を推測で補わない。

既存PACI、DB schema、API、端末認証、モデル学習条件の変更はない。本文と状態は既存LIVE_RACEペイロードの追加フィールドであり、旧観測も読み込める。

## 配置と復旧

Webの検証済みproduction buildと、同じmainの取得ワーカーを配置する。ワーカーは `python3 -m collector.service install --config <既存private config> --start` でversioned runtimeへ設置する。認証設定・ブラウザプロファイル・観測・研究DBを保持する。

Webの復旧先は今回の配置前の `dpl_FpxdFQ4gZVFBjoVUm3p8e7CW6pW4`（`https://race-analyzer-m5rqkv5mp-team-mj2.vercel.app`）。ワーカーは設置先の旧runtimeとバックアップplistから戻す。観測は追記方式で、取得済み記録は削除しない。

## 検証対象

純粋関数とcollectorテストで全頭照合・両段階コメント・空欄・オプション案内・失敗・実取得日時を確認する。ブラウザでは締切前から参考表示への切替、ACE予想の不変、390px幅、既存の各馬詳細への遷移を確認する。実運用確認の日時・配置ID・commit・結果は非公開のリリース記録に保存する。
