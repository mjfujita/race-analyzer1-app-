# 取消馬を含むレースのグループ登録（2026-11-28）

利用者の実画面で、京都11Rの「グループを登録」が無効で、「出走取消を含むため登録を保留しています」と表示されていることを確認した。本番の読取データでも9番ネーロノワールの取消、残る10頭の全単勝オッズ、未登録を確認した。配信版は容量対策の1d2e9a8。今回は保存容量ではなく、取消馬が1頭でもいるとグループの独立登録全体を止める仕様が原因。

## 変更

- 結果に使うグループの独立登録は、取消馬を除いた全出走馬を保存する。
- 画面に取消馬の馬番・馬名と、登録対象の頭数を表示する。
- 登録する馬別確率も出走馬のみに限定する。未算出の確率を補間・捏造しない。
- APIはクラウド同期済みの最新出走情報から取消を除き、登録対象の馬番・馬名・全頭数が一致する場合のみ受け付ける。任意の馬の除外や取消馬の混入は許可しない。
- 以前の登録、保存済み予想、結果、購入情報を変更しない。訂正・更新はこれまで通り追記する。
- 登録データ形式・認証・確率モデル・取得ワーカー・DB schema/migrationは変更しない。取消を含むレースの予想・購入関連の保留ルールは今回の対象外。

## 検証・反映

Nodeで取消後の登録、任意除外・取消混入の拒否、同じIDの再送、取消前の履歴保持、結果照合を検証。架空データの認証API・ストアに接続したChrome E2Eで取消を除いた登録、復元、更新、スマートフォン幅を確認する。

同じグループ登録障害に対する先の本番反映依頼を継続し、検証後に反映する。実レースの登録を検証目的で作成しない。反映後の京都11Rではボタンの有効化だけ確認し、利用者の代わりにグループ登録や購入を行わない。反映結果・検証数・復旧先は当該PRへ記録する。
