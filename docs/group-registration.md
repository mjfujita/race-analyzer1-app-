# ユーザー設定グループの独立登録

## 利用手順

1. レースの「グループ・買い目」で区切りを自分で調整する。
2. 「グループを登録」を押す。全出走馬の所属だけを登録し、着順予想・買い目・購入は作らない。「候補」のチェック解除は買い目だけに適用し、登録グループの頭数・所属を減らさない。
3. 「登録グループの結果を見る」で結果へ進む。予想未登録のレースにも、実際の1〜3着の群・群の頭数・登録時点の確率（取得済みの場合）を表示する。
4. 当日の群別着順回数は、各レースの最後の独立登録を1回だけ採用する。グループ未登録、結果待ち、結果競合・異常結果は数えない。予想から分類を自動転記しない。
5. 再編集後は「グループ登録を更新」を押すまで結果の分類を変えない。観測の追加同期も同じ。登録時の観測と手動の区切りを再表示し、登録履歴は展開して確認できる。

予想は保存時のグループ・馬番・全買い目を保持する。「予想（保存時）」と「結果（登録グループ）」は別の分類であることを表示する。買い目への包含は保存した馬番で照合し、再分類で的中扱いを変えない。

## 保存・API

- 新しい `group-registration` 形式にrace、全field、snapshot、grouping、任意の確率、実登録日時、replacesIdを記録する。slots、券種、買い目、配分は持たない。
- localStorage: `race-group-registration:v1:{encodedUser}:{YYYYMMDD}`。旧journalとは別キー。旧クライアントのjournal再保存によって消えない。
- private既存bucket: `{owner}/v1/group-registrations/{date}/records|links/...`。上書きせず追記し、親IDのcreate-only予約で二端末の競合更新を防ぐ。同一ID・内容の再送は冪等。
- 本人／承認端末限定 `POST /api/companion {action:"save-groups",record}`。既存の認証・same-origin検査を使う。collectorには書込権限を追加しない。
- 本人限定journal GETに `registrations` と受付時刻を追加。旧prediction/resultsは変更しない。同期済みsnapshotとオッズ・取得時刻・出走馬・発走時刻を照合し、他レース・未来日時・不明馬・競合を拒否する。
- 接続時はクラウド成功後にローカルと結果へ採用する。通信失敗は設定を保持し、登録状態の再読込後に再送できる。同一内容の再送は同一IDを使う。
- 発走後の登録を明記し、過去時点へ遡らせない。確率不足は未取得表示。再分類時に結果から確率を推定しない。
- DB schema / migration / 認証・RLS変更なし。取込ワーカー・学習・購入・精算データは変更しない。既存予想を独立登録へ自動移行しない。

- lint / typecheck / build成功。Node 181件、Playwright 67件成功。
- 空状態、未登録、手動結果のみ、グループ更新、予想固定、端末間復元、競合、通信失敗と再送、観測追加、破損した保存データ、未認証・別ユーザー・collector拒否を検証。

- `npm run dev -- --host 127.0.0.1 --port 5188 --strictPort`
